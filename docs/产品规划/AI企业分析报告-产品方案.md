# AI 企业分析报告 · 产品方案

> 版本 v0.1 ｜ 2026-11-05 ｜ 极增科技（极增商界）
> 报告模板参考：[样例/奥托立夫战略评估报告.pdf](样例/奥托立夫战略评估报告.pdf)
> 给 AI 开发用的技术规格在 `.codex-context/REPORT_SPEC.md`，本文是给人看的方案。

---

## 0. 一页总结

- **做什么**：面向 100–150 人成长型企业的「AI 辅助企业分析报告」。企业在线答题、上传资料，AI 收集外部信息、逐题打分、起草报告，再由审校人复核后交付。
- **报告长什么样**：完全参照奥托立夫样例的结构和版式，包括六维 24 题、八域 32 项、四象限、三地平线、证据分级等，约 20 页。原问卷是针对成熟期企业的，我们把它改造成「通用生命周期版」，同一套题判断企业处在哪个阶段，处方随阶段变化。
- **第一期上线两档**：
  - **免费简版**：老板 15 分钟自测，全自动出结果，用于官网获客。
  - **标准报告**：管理层多人作答，加上资料上传，AI 起草，人工审校，目标 72 小时交付。
- **AI 的定位**：AI 负责收集、整理、打分建议、起草和自查，**人负责最终判断**。所有分数由程序按规则计算，AI 写的每个数字都必须注明出处，没有出处的只能标为「C 级假设」。
- **审校人**：初期由我们自己（你或老板）审校，系统里做一个简单的审校后台。
- **模型**：测试阶段先用 DeepSeek，正式使用阿里云百炼。系统里做一层「模型切换」，换模型不用改业务代码。同时预留**本地部署开源模型**的选项（如千问 27B 规模），让数据不出公司；是否采用由 M2 阶段的质量对比来决定，见 7.3。
- **排期**：约 10 周做到试点，即能给 3–5 家种子客户出真实报告。第一步是把题库和评分标准定下来。

## 1. 产品定位

| 项目 | 内容 |
| --- | --- |
| 目标客户 | 100–150 人的成长型企业，决策人是老板或总经理 |
| 客户要解决的问题 | 企业现在处在哪个阶段？哪里卡住了？接下来先做哪三件事？ |
| 和传统咨询的区别 | 传统诊断要 2–4 周、费用几万到几十万；我们用 AI 把交付压到 72 小时，价格降一个数量级，审校人只把关关键判断 |
| 和纯 AI 报告的区别 | 有方法论（六维、八域、四象限）、有证据分级、有人工审校，结论可以追溯到出处 |
| 和后续产品的关系 | 报告里的「三条可验收动作」和行动计划，后面可以导入「经营工作台」持续跟进 |

## 2. 报告模板（以奥托立夫样例为蓝本）

### 2.1 报告结构

| 章节 | 内容 | 样例页码 |
| --- | --- | --- |
| 封面 | 企业名称、4 个关键数字（六维总分、阶段判定、两个关键经营指标）、评估框架、基准日、免责声明 | 1 |
| 评估摘要 | 总分、阶段、四象限位置、八域均分；**五条结论**（每条有依据、含义、证据等级）；处方一句话 | 3–4 |
| 一、企业基本情况 | 企业档案卡；业务、区域、客户结构；**资料完备度盘点**（决定这份报告的可信程度） | 5–6 |
| 二、生命周期六维诊断 | 6 个维度各 4 题，共 24 题，每题 1–5 分，附证据和等级；合计 120 分，判定所处阶段 | 7–9 |
| 三、战略能力八域评估 | 8 个领域各 4 项，共 32 项；每项打三个分：现状 S、对标 B、未来重要性 I；**缺口 = I − S**；附雷达图 | 10–13 |
| 四、战略更新度与三地平线 | H1 核心业务、H2 相邻业务、H3 新兴业务的资源占比（现状 vs 建议）；战略更新度打分 | 14 |
| 五、核心能力筛选 | 用四条标准（客户价值、相对优势、难以模仿、可延展）筛出核心能力，并登记每项能力的「负债面」 | 15–16 |
| 六、执行约束与 RACE | 资金、人才、见效窗口三项约束；RACE 四项自评（可靠度、认同度、清晰度、支持度） | 17 |
| 七、开放题与假设登记 | 三个开放题（最不该丢的业务、最该砍的投入、最怕的竞争变量）；所有 C 级判断登记为待验证的假设 | 18 |
| 风险提示 | 「这个结论可能错在哪」：列出反向证据，以及每条对结论的影响 | 19 |
| 结论与建议 | **三条可验收的战略动作**（量化口径、验收时点、责任人）；需要企业补充的资料清单 | 20 |
| 附录 | A 评分汇总与判定区间；B 四象限图；C 证据分级汇总 | 21–23 |

### 2.2 报告里的三套评分模型

1. **六维定阶段**：六个维度共 24 题。注意：**分越高代表越接近成熟期，不代表经营越好**。例如「近三年新品收入占比低」在这套题里记高分，因为这是成熟期的特征。所以六维总分的作用是判断企业处在哪个阶段：
   | 总分 | 阶段 | 处方方向 |
   | --- | --- | --- |
   | < 72 | 成长期 | 规模复制优先，避免过早分散资源 |
   | 72–83 | 扩张后期 | 规模复制 + 组织建设，先不急于讲第二曲线 |
   | 84–95 | 成熟临界 | 补组织能力，验证第二曲线，暂不收缩主业 |
   | ≥ 96 | 典型成熟期 | 效率再定义 + 第二曲线 + 资本配置 |

   我们的客户大多在前两个区间。成长期内部可能还要再细分，比如初创和成长；这个分界线需要在校准时定。
2. **八域看缺口**：32 项能力，每项打现状 S、对标 B、未来重要性 I 三个分，缺口 = I − S。缺口最大的几项，就是企业最该投入的方向。雷达图上蓝线是现状、橙线是未来要求，**看形状比看面积更重要**。
3. **动能 × 更新度定象限**：增长动能（由六维里的 A 维换算）和战略更新度组成四象限：① 成长/扩张期 ② 扩张后期 ③ 成熟期 ④ 停滞/衰退前夜。每个象限对应不同的处方。

### 2.3 证据分级（报告可信度的核心）

| 等级 | 含义 | 在我们产品里的来源 |
| --- | --- | --- |
| **A 硬数据** | 有文件或数据直接支撑 | 企业上传的财务报表、合同、制度文件；外部数据接口返回的工商、专利、招投标等记录 |
| **B 结构化判断** | 多个来源交叉印证的判断 | 多位管理层答案一致；行业报告或公开数据推算；AI 联网搜索到的可信来源 |
| **C 推断假设** | 只能推测，尚未验证 | AI 基于结构的推演；只有一个人回答且无资料佐证；资料缺失时的估算 |

规则：**每个分数、每条结论都必须标等级**；所有 C 级判断必须登记进「假设清单」，并写明怎么验证；全报告的 A/B/C 比例决定封面上的「置信度」（高 / 中高 / 中 / 低）。

### 2.4 从上市公司样例到中小企业的改动

| 样例的做法 | 我们的做法 |
| --- | --- |
| 数据来自年报、季报、评级报告 | 数据来自管理层问卷、企业上传的报表、外部企业数据接口和 AI 联网搜索 |
| 题目针对成熟期（如 ROCE、回购、董事会独立性） | 题目改成中小企业语言，例如「投入资本回报」改为「投入产出与回本周期」，「回购与分红」改为「利润分配与再投资」，「董事会制衡」改为「决策机制与制衡」 |
| 对标对象是最强竞争对手（ZF） | 由企业填写「最强的 1–2 个竞争对手」，AI 收集公开信息后给出对标分，审校人确认；以后积累同行业、同规模的基准库 |
| 管理层访谈留到下一步 | 标准报告用多人问卷代替访谈；深度诊断（以后）再加入访谈 |
| 一人分析 | 新增「老板与管理层认知差」分析：同一道题，老板和高管打分差距大的地方，往往就是管理问题所在。这是中小企业最有价值的发现之一 |

## 3. 第一期的两档产品

| | 免费简版 | 标准报告 |
| --- | --- | --- |
| 用途 | 官网获客，留下线索 | 核心收费产品 |
| 谁来答 | 老板一人 | 老板 + 3–5 位高管，各自作答 |
| 题量 | 约 20 题，15 分钟（六维每维 2 题，八域每域 1 题自评） | 六维 24 题 + 八域 32 项 + 开放题，每人约 40 分钟 |
| 资料 | 不需要 | 上传财务报表（近三年）、组织架构、核心制度等，可选 |
| 外部数据 | 只查工商基本信息 | 企业数据接口 + AI 联网搜索 |
| 产出 | 阶段判定、八域雷达图、3 条关键提示，在线查看 | 完整报告约 20 页，在线查看 + PDF 下载 + 线上解读 |
| 是否人工审校 | 否，全自动；页面上注明「AI 自动生成、仅供参考」 | 是，审校人逐条复核后才交付 |
| 交付时间 | 即时 | 目标 72 小时（从资料齐全起算） |
| 转化 | 结果页引导「升级为标准报告」 | 结尾引导深度诊断或经营工作台 |

**深度诊断**（顾问入企访谈 + 专项方案）放在后续版本，用的是同一套报告引擎，再加上访谈录音转写和证据提取。

## 4. 标准报告的生产流程

| # | 环节 | 谁来做 | 做什么 | 预计耗时 |
| --- | --- | --- | --- | --- |
| 1 | 下单与建档 | 客户 | 付款或获得试用资格，填写企业名称、行业、规模、主要竞争对手 | 5 分钟 |
| 2 | 邀请作答 | 客户 | 老板发链接邀请高管作答；系统提醒、追踪进度 | 1–3 天 |
| 3 | 上传资料 | 客户 | 上传报表、组织架构、制度等，系统提示还缺什么 | 与第 2 步并行 |
| 4 | 资料解析 | AI | 从上传的文件里提取关键数字（收入、毛利、现金流、人数等），标注页码出处 | 分钟级 |
| 5 | 外部信息收集 | AI + 数据接口 | 查询工商、股权、专利、招投标、舆情；联网搜索行业和竞品信息 | 分钟级 |
| 6 | 逐题打分建议 | AI | 综合问卷、资料、外部信息，对 24 题和 32 项给出建议分、理由、证据和等级；分析多人答案的差异 | 分钟级 |
| 7 | 计分与判定 | 程序 | 按固定规则算总分、阶段、缺口、象限、置信度。**不交给 AI 算** | 秒级 |
| 8 | 报告起草 | AI | 起草五条结论、各章节判断、三地平线、核心能力、RACE、假设清单、反向证据、三条动作 | 分钟级 |
| 9 | 自动质检 | AI + 程序 | 检查数字和出处是否一致、分数和文字是否矛盾、C 级是否都进了假设清单、有没有空泛表述 | 分钟级 |
| 10 | 人工审校 | 审校人 | 在审校后台逐条「接受 / 修改 / 驳回」，重点看五条结论和三条动作；所有修改留痕 | 目标 2–4 小时 |
| 11 | 交付 | 系统 + 审校人 | 生成在线报告和 PDF，通知客户；预约线上解读会 | 即时 |

## 5. AI 在哪里辅助、在哪里不让它做

| 环节 | AI 做什么 | 不让 AI 做什么 | 人怎么把关 |
| --- | --- | --- | --- |
| 问卷 | 根据行业改写题目说明；答案模糊时追问一句；检查答案是否前后矛盾 | 不能替企业作答 | 题库由审校人定稿 |
| 资料解析 | 读报表、PDF、Excel，提取数字并标注出处页码 | 不能补全缺失的数字 | 审校时可以点开出处核对 |
| 外部信息 | 整理接口返回的数据；联网搜索并摘要 | 搜索结果不能作为 A 级证据 | 审校人可以删除不可信来源 |
| 打分 | 给出建议分 + 理由 + 证据 + 等级 | 不能计算总分、阶段、象限（由程序算） | 审校人确认或改分，改分要写原因 |
| 起草 | 写结论、含义、处方、风险提示、假设清单 | 不能写没有出处的数字；不能给投资建议 | 审校人逐条确认 |
| 质检 | 自查矛盾、空话、缺漏 | — | 质检不通过的项会在审校后台标红 |
| 学习改进 | 汇总审校人的修改，找出 AI 常错的地方 | 不自动改题库和评分规则 | 我们定期据此调整提示词和题库 |

**四条硬规则**：
1. 每个数字必须有出处（问卷第几题、哪份文件第几页、哪个接口），否则只能写成 C 级假设。
2. 所有计分、区间判定由程序完成，结果可以复算。
3. 每条结论都要配「可能错在哪」的反向证据，避免只说好话或只说坏话。
4. 付费报告必须经过人工审校才能交付；审校前客户看不到草稿。

## 6. 数据来源

| 来源 | 内容 | 证据等级 | 说明 |
| --- | --- | --- | --- |
| 管理层多人问卷 | 24 题 + 32 项 + 开放题 | 单人回答为 C；多人一致为 B；有资料支撑为 A | 可以分析老板与团队的认知差 |
| 企业上传资料 | 财务报表、组织架构、制度、合同样本 | A | AI 自动提取，标注页码 |
| 外部企业数据接口 | 工商、股权、分支机构、专利、招投标、司法、舆情 | A（官方登记类）/ B（舆情类） | 企查查、天眼查等按调用次数付费，需要询价并签约 |
| AI 联网搜索 | 公开新闻、行业报告、竞品信息 | B 或 C | 必须保留来源链接，审校人可以剔除 |

## 7. 系统组成与技术方案

### 7.1 系统模块

```
客户端（手机优先）        审校后台（电脑）
  ├ 免费简版问卷            ├ 报告列表与进度
  ├ 标准报告问卷（多人）    ├ 逐题审校（建议分 / 证据 / 出处）
  ├ 资料上传               ├ 结论与动作编辑
  └ 报告查看 / 下载         └ 修改留痕、一键发布
            │                       │
            └──────── 后端服务（一个）────────┘
                 ├ 题库与评分规则（版本化配置）
                 ├ 计分引擎（程序计算，可复算）
                 ├ AI 流水线（解析 → 收集 → 打分 → 起草 → 质检）
                 ├ 模型切换层（DeepSeek / 阿里云百炼）
                 ├ 外部数据接口
                 ├ 报告渲染（HTML 模板 → PDF）
                 └ 账号、订单、支付（接支付宝 / 微信）
                          │
                 PostgreSQL 数据库 + 文件存储（先本地，后迁 OSS）
```

### 7.2 技术选型（建议）

| 部分 | 选择 | 原因 |
| --- | --- | --- |
| 后端 | Python（FastAPI） | 读 PDF、Excel 和调用 AI 的生态最成熟 |
| 数据库 | PostgreSQL | 结构化数据和 JSON 都能存，后续可迁阿里云 RDS |
| 前端 | 先用和官网一致的轻量方案，问卷和审校后台单独做页面 | 上线快；后面工作台再上完整前端框架 |
| 报告 PDF | HTML 模板 + 无头浏览器导出 | 版式能做到和样例一致，中文排版好 |
| 图表 | 雷达图、四象限图由程序生成 SVG | 清晰、可复现 |
| 大模型 | 测试阶段用 DeepSeek，正式用阿里云百炼（可调用千问、DeepSeek 等） | 国内模型，数据不出境；可申请阿里云「OPC 创新助力计划」的 Token 补贴 |
| 服务器 | 需要一台 **Linux 服务器（建议 2 核 4G）** | 现在的试用机是 Windows、到期也早，不适合跑这套系统；PDF 导出和数据库需要 4G 内存 |

### 7.3 本地部署模型（保密方案，待评测）

为了让企业数据不经过第三方模型服务商，可以本地部署开源模型（例如千问的 27B 规模版本）。系统的「模型切换层」从一开始就支持云端和本地两种方式，所以要不要本地部署，**用评测结果来决定，不影响开发进度**。

| 项目 | 说明 |
| --- | --- |
| 保密效果 | 企业资料只存在我们自己的服务器和机器上，不发送给任何模型服务商。可以作为面向保密要求高的客户的卖点 |
| 硬件需求 | 27B 模型做 4-bit 量化后，权重约 16–18GB；加上处理长文档所需的上下文内存，建议 **48GB 以上显存，或 64GB 以上统一内存的 Mac**。可选：64–128GB 的 Mac Studio（省心、安静，速度一般），或者配 48GB 显卡的 GPU 主机（更快）。现在这台 16GB 的 MacBook 跑不动 |
| 速度 | 报告是后台批量生成，不需要实时。估计一份标准报告在 Mac Studio 上需要几十分钟到一两个小时，在 72 小时交付时限内可以接受 |
| 质量 | 27B 模型在长文档理解和深度分析写作上，通常弱于云端旗舰模型。资料提取、逐题打分这类结构化任务一般够用；五条结论和处方这类关键写作需要实测对比 |
| 部署位置 | 网站和数据库在阿里云，本地模型在办公室的机器上，主动去服务器领取任务，处理完再传回结果，不需要对外开放端口。也可以在阿里云租 GPU 服务器，但月费较高 |
| 前提 | 确认该模型确实开源，并且许可证允许商业使用 |

**建议做法**：M2 阶段用同一家测试企业，分别跑云端旗舰模型和本地 27B 模型，由审校人盲评对比。
- 如果本地模型质量够用：全部改为本地，再采购硬件。
- 如果不够：采用「混合模式」，报表提取等敏感环节在本地处理，起草时只把脱敏后的结构化摘要发给云端；对有保密要求的客户提供「全本地」选项。

**不要在评测之前采购硬件。** 另外，使用云端模型时，也可以通过与服务商签订数据不用于训练的协议，从合同层面保护数据。

### 7.4 目录（按之前定的「一个仓库、多个子目录」）

```
apps/report/        问卷、报告查看页、审校后台
server/             后端（报告和以后的工作台共用）
packages/methodology/  题库、评分规则、判定区间（版本化）
```

## 8. 数据安全与合规

- 企业资料加密存储，只用于生成该企业的报告；客户可以申请删除。
- 审校后台按账号授权，所有查看和修改都留记录。
- 发送给大模型的内容尽量去掉身份信息，例如用代号代替企业名。和模型服务商确认不把数据用于训练。
- 报告注明「基于企业提供资料与公开信息整理推演，不构成投资建议」。样例里已有类似声明，沿用即可。
- 用户协议和隐私政策需要在上线前准备好，支付审核也会检查。

## 11. 主要风险与对策

| 风险 | 对策 |
| --- | --- |
| 题库是从报告反推的，评分标准可能不够准 | M0 用奥托立夫回填校准；试点期按审校修改持续调整；题库做版本管理 |
| AI 编造数字或结论 | 出处强制规则 + 程序计分 + 自动质检 + 人工审校 |
| 中小企业资料少，报告空洞 | 资料完备度盘点写进报告，坦白告诉客户置信度；用多人问卷和认知差弥补 |
| 审校人手有限，72 小时难保证 | 审校后台把重点（五条结论、三条动作、改分项）排在最前面；先控制试点数量 |
| 对标数据冷启动 | 先用客户指定的竞品 + 公开信息；每做一份报告就沉淀一份行业样本 |
| 方法论与样例的版权 | 增长极方法论已确认可用；报告模板是极增商界自有 |
