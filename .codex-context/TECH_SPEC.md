## 0. Decisions (2026-11-05, confirmed by user)
- Form: **web app (B/S)**, no desktop software, no 小程序 for now. Client execs fill questionnaire via mobile H5 link (no login).
- Dev: user + AI (Claude) writes code → keep stack simple, few moving parts, easy to deploy, heavy tests on scoring/pipeline.
- Backend: **Python**. Data: default 阿里云; per-client option = whole stack + local Qwen on office machine.
- Review/editing: **structured report editor in browser** ("like Google Docs"): text blocks editable; scores/charts are data-bound locked blocks edited via a score panel (change requires reason; totals/charts recompute). Comments + version history.
- Collaboration: **one editor at a time (edit lock), others comment**. No realtime co-editing (may add Yjs later).
- Delivery to client: **PDF + 解读会**. Client never logs in.
- Server: buy Linux before the editor goes online for the boss (≈ week 4–5, end of 1a / start of 1b). Phase 1a runs on user's Mac.

## 3. Pipeline design
- Every AI step = prompt template (versioned) + typed input + Pydantic output schema; invalid JSON → retry ≤2 then fail job visibly. Log every call to `LlmCall` (provider, model, prompt_version, tokens, cost, latency, request/response).
- Long docs: chunk annual report by section → extract **fact cards** `{metric, value, unit, period, page, quote}` → program re-checks number appears in quoted page text → later steps see fact cards + quotes only (not whole PDF).
- `suggest_scores`: per item → `{score, rationale, evidence_ids[], grade}`; grade rules from REPORT_SPEC §6 enforced by code (no evidence → C).
- `compute` = `app/scoring` (deterministic). AI never computes totals/stage/quadrant.
- `draft_sections`: per section, input = computed results + evidence; output = TipTap-compatible JSON (restricted nodes) with inline `evidence_ref` marks.
- `qa_check` (code + AI): every number has source; numbers match fact cards; score↔text contradictions; C items listed in hypotheses; exactly 5 conclusions / 3 actions; banned vague phrases list.
- Golden-set regression: `pytest -m golden` reruns Autoliv (+2) → compare item scores (MAE), stage, key numbers; run on every prompt/model change.

## 4. Editor (phase 1b)
- Layout: left = section outline with status (AI草稿/审校中/已定稿); center = document; right tabs = 评分面板 / 证据 / 批注 / 版本.
- Data blocks (locked in text): `scoreTable`, `radarChart`, `quadrantChart`, `stageBar`, `conclusionCard`, `actionCard`. Click → opens score panel / data form.
- Score change: requires reason → `ReviewEvent`; triggers recompute; sections whose text references changed items get flagged "数据已变，请复核".
- Comments: anchored to text range (mark id) or to item_id; threads, resolve.
- Edit lock: per report, heartbeat 30s, expires after 2 min idle; others read-only + comment.
- Versions: autosave draft every ~10s (debounced) to `SectionDraft`; explicit "保存版本" creates `ReportVersion` snapshot; diff AI-original vs final → per-report edit-rate metric.
- AI assist on selection (改写/精简/补证据): returns suggestion; user accepts → replaced; logged.
- Export: PDF (delivery) via render service; Word (phase 2).

## 6. Security & confidentiality
- HTTPS mandatory before any client link goes out; use subdomain of an ICP-filed domain (e.g. app.talentchain.net, later growthhub.cn).
- Internal accounts: password (argon2) + lockout; 2FA later. Questionnaire: per-respondent unguessable token links, expiry/revoke, no client accounts.
- Minimize data sent to LLM (fact cards/excerpts, not whole files when avoidable). Verify provider data-use terms (百炼/DeepSeek) before first paid client; confidential clients → local mode.
- AuditLog for view/edit/export. Nightly encrypted backups. Delete client data per contract at end.
- Local mode: entire compose + local model on office GPU box; outbound only (or offline).
