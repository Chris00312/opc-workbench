# DECISIONS

## 2026-10-08 UI 风格：Stripe 后台风格
- 选项：卡片堆叠的“AI 模板”风格 vs Stripe 后台风格。
- 决定：Stripe 风格（白底、细分隔线、表格、单一蓝色强调色、浅灰侧栏）。
- 原因：用户认为卡片风格显得廉价。以后的 UI 继续用这个风格。

## 2026-10-08 分阶段推进
- 决定：先做培训（用现成工具），再把 AI 工具产品化，最后做撮合平台。
- 原因：降低前期投入，先验证需求。

## 2026-10-14 部署方式：纯静态 + nginx
- 决定：静态页面打包，用户在自己的 VPS 上运行 deploy.sh。
- 原因：原型无后端；云端会话无法 SSH 到用户服务器。

## 2026-10-25 仓库不含敏感信息
- 服务器 IP、SSH 端口、密码一律不入库，文档里用占位符。原计划书 PDF 不入库。

## 2026-10-27 以增长极方法论作为 AI 工具的内核
- 选项：通用 AI 工具（行业常见问题库） vs 内置旧网站的增长极方法论。
- 决定：内置增长极方法论；新增面向企业主的「增长体检」作为获客和撮合入口。
- 原因：方法论是旧业务最值钱的资产，也是和市面 AI 训练营拉开差距的地方。用户回复“继续”，以下待定事项按默认推进：品牌仍用 OPC 工作台，方法论称“增长极”；先做企业端入口；版权待用户确认。

## 2026-10-27 产品形态：AI 增长诊断先行，订阅直接卖给企业
- 用户确认增长极方法论版权可以使用。
- 决定：第一个产品是 AI 增长诊断（手机 H5，简版免费留资，完整版单次收费，试用期人工复核）；之后的订阅工作台直接卖给企业，顾问作为可选陪跑。
- 原因：用户在选择卡片上选了“直接卖给企业”；诊断离老客户最近，最容易验证。
- 方案文档：https://claude.ai/artifact/3acrP1BAupzKRCrefK4kMG

## 2026-11-01 定位：中型企业 + 极增品牌
- 决定：公司“极增科技”，内容/报告品牌“极增商界”；主客户 100–150 人企业；个人/小机构订阅版是第二产品线，后做。
- 影响：OPC 顾问工作台（site/）作废。

## 2026-11-01 官网风格：深色科技风（参考 51WORLD）
- 选项：沿用 Stripe 后台浅色风 vs 用户指定的 51WORLD 官网风格。
- 决定：官网用深色 + 全屏视频 + 竖版产品卡 + 路线图，主色青绿 #19d3b0、辅色琥珀。Stripe 风格仍用于产品内部后台界面。
- 素材：只用 Pexels / Mixkit 可商用素材，本地托管（不外链），来源列在 credits.html。

- 用户反馈 v2 有“AI 卡片感”。决定：按钮、导航、区块完全按 51WORLD 做（纯黑、居中标题、小实心发光按钮、满版大图），禁用描边卡片、图标块、描边标签、渐变文字、小号英文眉标。主色仍为青绿 #1ed6b0。

## 2026-11-03 Logo：双峰
- 四个方向（折页 Z、负空间箭头、双峰、点阵）中用户选定双峰：白/黑色峰 + 青绿渐变峰 #7ff6dc→#14b593，叠合处 #0b6e5c；字标“极增科技”加宽字距 + 竖线 + JIZENG TECHNOLOGY。

## 2026-11-05 产品 1：AI 企业分析报告的方案决定
- 报告模板以奥托立夫样例为准（docs/产品规划/样例/）；题库从样例反推，再由用户/老板校准。
- 采用通用生命周期版：同一套 24 题判定阶段（<72 成长期 / 72–83 扩张后期 / 84–95 成熟临界 / ≥96 典型成熟期），处方随阶段变化。
- 第一期：免费简版 + 标准报告；审校初期由用户或老板负责。
- 八域以报告为准（财务与资本、市场与客户、运营与供应链、技术与创新、组织与人才、信息与数字化、流程与协同、战略与治理），官网 report.html 需跟着改。
- 数据来源四种都用：多人问卷、上传资料、外部企业数据接口、AI 联网搜索。
- 模型：测试先用 DeepSeek，正式用阿里云百炼；本地部署千问 ~27B 作为保密选项，M2 盲评后再决定，评测前不采购硬件。
- 计分与判定由程序完成，AI 只给建议分和文字；数字必须有出处，否则为 C 级并进假设清单。

## 2026-11-05 报告产品目标客户上移：中型企业起步，含上市公司
- 决定：目标客户从「100–150 人成长型企业」改为「中型企业起步、含上市公司」，即高净值、愿意付费的企业；不做自助免费简版（改为销售用的预诊断）；老板本人（资深顾问）负责审校和解读；价格未定。
- 影响：方案 docx、REPORT_SPEC、官网 report.html（仍写 100–150 人、免费体检）都需要改；原问卷更贴合这类企业，证据更容易拿到 A 级；保密和访谈的重要性上升。

## 2026-11-05 只有报告产品上移，公司整体定位保持综合
- 用户更正：「中型企业起步、含上市公司」只是企业分析报告的目标客户（这类报告一般大企业才买）；经营工作台面向小公司到成长型企业，超级个体面向一人公司和自媒体。
- 决定：官网首页、页脚、meta 写综合定位「从一人公司到上市公司」；报告页和报告卡片保留「面向中型企业与上市公司」；每张产品卡写各自的目标客户；路线图取消对 S3 的单独高亮。

## 2026-11-05 报告产品的软件技术方案
- 决定：做网页系统，不做安装软件、暂不做小程序；问卷用手机 H5 链接（免登录）。产品负责人主导 + AI 编写代码，技术栈求简单：Python（FastAPI）+ PostgreSQL（兼做任务队列，不用 Redis/消息队列）+ Vue 3；一套 Docker Compose，云端与本地同一套。
- 审校：用户要求「像 Google Doc 一样在网页里改」→ 采用结构化报告编辑器（TipTap 开源核心）：文字直接改，分数/图表为锁定数据块，在评分面板改分并必填理由，自动重算；一次一人编辑、其他人批注；不做实时协同。备选方案「网页版 Word（OnlyOffice）」因分数与图表会和文字脱节而放弃。
- 交付：客户只收 PDF + 解读会，不登录。数据默认阿里云，客户要求时整套本地部署 + 本地 Qwen。
- 服务器：阶段 1a 在 Mac 上开发；编辑器给老板在线使用前（约第 4–5 周）买 Linux 服务器。
- 细节见 .codex-context/TECH_SPEC.md。
